Co-signer for agent payments

Allowances let your agents spend without asking. Countersign makes sure they should.

Every payment out of a shared Kite allowance climbs a ladder of checks that gets stricter as more money is at risk: code rules, SERV reasoning, a Reppo network verdict, and finally your passkey. Each decision ships with a receipt.

      How a payment is checked

      Four rungs. Each one only runs when the one below can't settle it.

      Any rung can block. Any failure, whether a timeout, malformed output or missing verdict, escalates instead of approving. Nothing is paid until the receipt says approved.

      01

      Code rules

      Allow and deny lists, caps, your plain-English rules, lookalike payees, duplicate and split payments, unusual amounts, hidden instructions, and payees missing from Kite's directory.

      Runs on every paymentCost ~$0
      02

      SERV reasoning

      Does this purchase follow from the agent's task? A strict JSON schema validated in code, with SERV's PromptGuard and Shadow Agent on every call.

      Runs at ≥ $1 or new payeeCost ~$0.0008
      03

      Reppo verdict

      An independent network evaluation: accept proceeds, revise goes to you, reject blocks. Low-confidence accepts also go to you.

      Runs at ≥ $20 or a serious flagCost $0.22
      04

      Your passkey

      A one-shot Kite session scoped to exactly this payment. You approve it with your passkey, and the payment goes through that session only.

      Runs when Reppo says re-evaluateCost one tap

      Integrations

      Built on SERV, Reppo and Kite.

      Each integration is optional. A tier without credentials runs an offline stand-in, and every receipt says which mode answered.

      Connect an agent

      One config entry. Every payment goes through Countersign.

      Countersign ships as an MCP server. Any MCP-capable agent gets a countersign_pay tool and pays through it instead of calling Kite directly.
